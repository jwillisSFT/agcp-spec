This file is the human-readable mirror of `test-control-mapping.json`. It was regenerated after the Formal Test Cases, Test Matrix, and test mappings were synchronized. It maps each Formal TC to Governance Observation Points, standardized IF-005 precondition controls where useful, explicit external dependencies, and additional harness injection needs together with their current standardization disposition.

## Development status

The test-control, fixture-injection, and observation-point inventory remains under active development. A control listed here is a standardized capability that may be used when the assessed implementation advertises and proves runtime-bound support; the mapping does **not** assert that every reference implementation already implements every control or internal hook. The previously identified TC-081/TC-120/TC-121 internal injection needs are standardized by DS-050 controls. Implementation support remains profile/runtime dependent and must be discovered and proven through IF-003/IF-005.

## Runtime binding gate

A mapped IF-005 control establishes a Formal TC precondition only when all applicable conditions are satisfied:

1. IF-003 capability discovery reports `runtime_binding_status: BOUND`;
2. the typed control reaches `effect_status: EFFECTIVE`;
3. the governed request carries the same authorized `X-AGCP-Test-Scope`; and
4. where runtime consumption matters, readback reports `consumption_status: OBSERVED` with correlated GOP evidence.

`RECORD_ONLY`, `UNBOUND`, `PENDING`, or merely accepted/stored controls do not establish a Formal TC precondition. IF-005 may establish source or dependency conditions only; it may not inject the expected Governance Decision, Execution Authorization, GRF/CBA conclusion, PEP-profile mapping success, Enforcement Context, Structural Refusal, Derived Lifecycle State, Commit Boundary outcome, or conformance result.

## Additional harness injection needs and standardization disposition

### TC-081 — Every Action Follows Valid Lifecycle Transitions

- **`ASYNCHRONOUS_EXECUTION_DELAY_AND_TERMINAL_OUTCOME`** — `PROFILE_CONDITIONAL_DEVELOPMENT_OR_IMPLEMENTATION_DEPENDENT`. Use a bound PEP/external-target outcome adapter only when the assessed profile separates commitment from later execution. Do not inject DS-052 or lifecycle state directly. Standardized support: `PEP_OUTCOME_FIXTURE`

### TC-120 — Enforcement Decision Integrity

- **`ENFORCEMENT_CONTEXT_TAMPER_OR_SUBSTITUTION`** — `IMPLEMENTATION_SPECIFIC_OR_FUTURE_STANDARDIZATION_CANDIDATE`. A harness may need a controlled pre-PEP mutation path while leaving ordinary GRF construction and PEP validation active. No current DS-050 control directly injects Enforcement Context. Standardized support: No current DS-050 operation directly represents this need.
- **`GOVERNANCE_ENFORCEMENT_BINDING_MISMATCH`** — `IMPLEMENTATION_SPECIFIC_OR_FUTURE_STANDARDIZATION_CANDIDATE`. The negative path must test binding mismatch without injecting a desired refusal or commit outcome. Standardized support: No current DS-050 operation directly represents this need.
- **`NONFAITHFUL_OR_UNSUPPORTED_PEP_MAPPING`** — `PARTIALLY_STANDARDIZED`. Governance configuration may establish the mapping condition, but normal GRF profile selection and mapping validation must still run. Standardized support: `GOVERNANCE_CONFIGURATION_FIXTURE`

### TC-121 — Governance Enforcement Binding

- **`GRF_TO_PEP_CALLER_IDENTITY_MISMATCH`** — `PARTIALLY_STANDARDIZED_OR_TRANSPORT_SPECIFIC`. AUTHORITY_FIXTURE is suitable when caller authorization is resolved from an authoritative source. mTLS/workload-identity mismatch may require a transport-specific harness path. Standardized support: `AUTHORITY_FIXTURE`
- **`GOVERNANCE_ENFORCEMENT_BINDING_MISMATCH`** — `IMPLEMENTATION_SPECIFIC_OR_FUTURE_STANDARDIZATION_CANDIDATE`. Exercise an exact binding mismatch while preserving ordinary GRF/PEP validation and fail-closed semantics. Standardized support: No current DS-050 operation directly represents this need.
- **`COLOCATED_GDF_GRF_PEP_LOGICAL_BINDING_NEGATIVE_PATH`** — `IMPLEMENTATION_SPECIFIC_OBSERVATION_OR_INJECTION_NEED`. Co-location removes a network boundary but not logical authorization, binding, refusal, and evidence requirements; internal test hooks may be needed to prove the negative path. Standardized support: No current DS-050 operation directly represents this need.
