# TC-031 — Dual Authorized Conflicting Actions

## Purpose

Verify that the implementation satisfies **CR-031** by exercising the controlled scenario below and independently verifying every direct test-generating Normative Statement assigned by the current AGCP Requirements Traceability Matrix.

## Authoritative Traceability

- Primary Conformance Requirement: **CR-031 — Dual Authorized Conflicting Actions**
- Requirement Text: Authorization SHALL NOT imply unconditional future execution authority.
- Requirement Group: RG-2 — Execution Governance
- Applicable Conformance Level: L4 — Execution Authorization Control
- Test Case Approval Status: Approved
- Test Case Approval Authority: AGCP Specification Owner
- Test Case Approval Date: 2026-07-19
- Direct Test-Generating NS IDs: NS-4.5-01, NS-4.11-01, NS-8.1-02, NS-8.2-01, NS-8.2-02, NS-8.4-01, NS-8.5-01, NS-8.5-02, NS-8.5-03, NS-8.6-01, NS-8.7-02, NS-13.6-05
- Conditional NS IDs: None
- Supporting/Contextual NS IDs: NS-8.2-03, NS-8.2-04, NS-8.3-01, NS-8.3-02, NS-8.6-03, NS-8.7-01, NS-8.7-03, NS-13.6-06

## Test Objective

Two conflicting proposals, P-031-A and P-031-B, are independently authorized against the same governed resource state. P-031-A is committed first and changes Canonical State CS-031. The implementation is then instructed to commit P-031-B using its earlier authorization without revalidating current execution and continuation conditions.

## Overall Test Procedure

1. Load the baseline tenant, governance domain, proposal or controlled artifact, policy, qualified authoritative sources, governance configuration, and evidence prerequisites.
2. Execute the primary scenario for CR-031 and record the complete governance-stage sequence and authoritative outcomes.
3. Execute each direct Normative Statement subtest below using an isolated processing attempt or a clearly identified phase of the same attempt.
4. Execute the conditional subtest when its applicability condition is present; otherwise document Not Applicable with implementation-profile evidence.
5. Inspect supporting and contextual constraints as integrated properties of the test path without counting them as separate direct NS verifications.
6. Preserve all inputs, outputs, authoritative source references, evidence artifacts, ordering information, and assessor observations required for independent reproduction.

## Direct Normative Statement Verifications

### TC-031-A01 — NS-4.5-01

**Core Specification Section:** 4.5 Authorization

**Normative Statement:** Authorization is evidence and an input to later governance processing. It SHALL NOT itself constitute authority at commitment, final execution admissibility, or execution.

**Relationship:** Specifies — Direct

**RTM Test Assertion:** Exercise the violating or negative path and verify that the implementation enforces: Authorization is evidence and an input to later governance processing. It SHALL NOT itself constitute authority at commitment, final execution admissibility, or execution.

**Procedure**

1. Establish the controlled TC-031 baseline using the Test Inputs and Setup, with all conditions unrelated to TC-031-A01 held valid and recorded.
2. Create a conforming control in which the implementation can satisfy the following exact obligation without relying on an unrelated refusal: Authorization is evidence and an input to later governance processing. It SHALL NOT itself constitute authority at commitment, final execution admissibility, or execution.
3. Create a valid control path containing an attributable governance decision, execution authorization, current authority lineage, Canonical State basis, target, tenant, scope, validity interval, Governance Version, and Commit Boundary request as applicable.
4. Process the unchanged bound artifacts through the authorized downstream stage and record which artifact is consumed, the current authority re-derivation result, binding validation result, and final admissibility or enforcement outcome.
5. Create isolated negative variants by changing or removing, one at a time, the Proposal Identity, decision or authorization reference, authority lineage, target, tenant, scope, Canonical State basis, policy, evidence, lifecycle state, validity interval, bind condition, or Governance Version relevant to the statement.
6. Attempt progression or execution with each negative variant and verify that authorization is not treated as execution authority, no stale or detached artifact is accepted, and no governed consequence occurs without successful current validation and applicable enforcement.
7. Where the statement distinguishes evaluation, authorization, commitment, realization, and execution, verify each stage produces only its defined artifact or outcome and does not perform the downstream stage.
8. Confirm all accepted and refused cases are attributable to the exact decision, authority, binding, state, and enforcement basis.

**Expected Result**

Only the unchanged, currently valid, correctly bound and re-derived authority path can progress to the applicable downstream stage. Prior authorization alone never constitutes final admissibility or execution authority, and every stale, substituted, detached, cross-boundary, or bypass case is prevented.

**Required Evidence**

- Authoritative decision and execution-authorization artifacts
- Current Authority Lineage and re-derivation result
- Binding fields for Proposal, target, tenant, scope, state, policy, evidence, validity, and Governance Version
- Successful unchanged-path result
- One-field-at-a-time substitution, omission, stale-state, and bypass results
- Commit Boundary, enforcement, refusal, and no-governed-consequence evidence

**Pass Criteria**

TC-031-A01 passes only when the implementation accepts only the exact currently valid bound path, preserves stage separation, re-derives authority where required, refuses every substitution or bypass, and prevents any unauthorized governed consequence, thereby independently demonstrating the complete requirement of NS-4.5-01.

**Failure Conditions**

TC-031-A01 fails if any required trigger, validation, transition, binding, outcome, or evidence element described above is absent or contradicted; a generic refusal occurs without proving the statement-specific basis; an invalid, stale, substituted, unauthorized, out-of-scope, or bypass path is accepted; a prohibited governed consequence occurs; or the result cannot be independently reproduced from attributable authoritative evidence.
