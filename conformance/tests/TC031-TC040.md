# TC-031 — Dual Authorized Conflicting Actions

**Requirement**
CR-031 — Authorization SHALL NOT imply unconditional future execution authority.

**Conformance Level**
L4 — Execution Authorization Control

### Preconditions

* Resource R exists.
* Action A1 and Action A2 target the same governance object.
* Both actions independently satisfy policy requirements.
* Both actions reach AUTHORIZED state.

### Request / Scenario

Submit:

```text
A1 = Delete Resource R
A2 = Modify Resource R
```

Both become AUTHORIZED.

Commit A1 first.

Attempt to commit A2 afterward.

### Simulated Execution Trace

Step 1 — A1 submitted.

Step 2 — A1 evaluated.

Step 3 — A1 authorized.

Step 4 — A2 submitted.

Step 5 — A2 evaluated.

Step 6 — A2 authorized.

Step 7 — Commit A1.

Step 8 — Resource R removed.

Step 9 — Commit A2 attempted.

Step 10 — Commit-time admissibility re-evaluated.

Step 11 — Target resource no longer exists.

Step 12 — A2 refused.

### Ledger Delta

```text
Proposal(A1)
Authorization(A1)

Proposal(A2)
Authorization(A2)

Commit(A1)

Refusal(A2)
Reason=TargetResourceUnavailable
```

### Derived State After Request

```text
A1 = EXECUTED
A2 = REFUSED
```

### Expected Result

```http
409 Conflict
```

### What This Test Proves

Authorization is not equivalent to execution authority.

## TC-035 — Canonical State Changes During HITL

**Requirement**
CR-035 — Escalated actions SHALL be re-evaluated against current canonical state before execution.

**Conformance Level**
L4

### Preconditions

* Action enters PENDING_HITL.
* State S0 exists.
* State later changes to S1.

### Request / Scenario

Receive quorum approval after state change.

### Simulated Execution Trace

Step 1 — Proposal submitted.

Step 2 — Escalation triggered.

Step 3 — HITL review begins.

Step 4 — Canonical state changes.

Step 5 — Quorum completed.

Step 6 — Authorization requested.

Step 7 — Re-evaluation performed.

Step 8 — Admissibility re-computed.

### Ledger Delta

```text
Proposal(A)

Escalation(A)

StateTransition(S0→S1)

HITLApproval

Reevaluation
```

### Derived State After Request

Either:

```text
AUTHORIZED
```

or

```text
REFUSED
```

depending on S1.

### Expected Result

Authorization based on S1, never S0.

### What This Test Proves

HITL approvals do not bypass commit-bound governance.
