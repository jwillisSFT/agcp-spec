# TC-091 — Degraded Governance Condition Detected

**Requirement**
CR-091 — A governance object SHALL enter DEGRADED state when one or more governance assumptions, evidence artifacts, contextual dependencies, authorization conditions, or canonical-state dependencies required for continued admissibility can no longer be verified.

**Conformance Level**
L2 — Ordered Governance Mediation

### Preconditions

* Proposal exists in AUTHORIZED state.
* Supporting evidence or governance dependency was valid at authorization time.
* Continuous governance monitoring is enabled.

### Request / Scenario

A previously authorized proposal loses a required governance dependency before commit.

### Simulated Execution Trace

Step 1 — Proposal is authorized.

Step 2 — Continuous monitoring evaluates governing conditions.

Step 3 — Required evidence or dependency becomes unverifiable.

Step 4 — Degradation condition is detected.

Step 5 — Proposal lifecycle state transitions to DEGRADED.

### Ledger Delta

```text
AuthorizationGranted

DegradationDetected
Reason=GovernanceDependencyUnverifiable

LifecycleStateChanged
From=AUTHORIZED
To=DEGRADED
```

### Derived State After Request

```text
DEGRADED
```

### Expected Result

```http
200 OK
```

### What This Test Proves

The system can detect and represent loss of governance confidence as a first-class lifecycle state.

# TC-092 — DEGRADED Is Non-Terminal

**Requirement**

**Conformance Level**
L2 — Ordered Governance Mediation

### Preconditions

### Derived State After Request

```text
DEGRADED
```

### Expected Result


# TC-093 — Re-Evaluation Required Before Execution

**Requirement**
CR-093 — Objects in DEGRADED state SHALL require re-evaluation prior to authorization retention or execution.

**Conformance Level**
L4 — Execution Authorization Control

### Preconditions

* Proposal exists in DEGRADED state.
* A prior authorization artifact exists.
* Commit request is submitted without successful re-evaluation.

### Request / Scenario

Attempt to commit a degraded proposal using its prior authorization.

### Simulated Execution Trace

Step 1 — Commit request received.

Step 2 — Prior authorization artifact retrieved.

Step 3 — Lifecycle state evaluated.

Step 4 — DEGRADED state detected.

Step 5 — System requires re-evaluation.

Step 6 — Commit is denied pending re-evaluation.

### Ledger Delta

```text
CommitAttempt

ReevaluationRequired

Refusal
Reason=DegradedStateRequiresReevaluation
```

### Derived State After Request

```text
DEGRADED
```

### Expected Result

```http
403 Forbidden
```

### What This Test Proves

A degraded object cannot rely on stale authorization to cross the commit boundary.
