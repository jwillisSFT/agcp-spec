## Direct Normative Statement Verifications

### TC-011-A01 — NS-13.6A-03

**Core Specification Section:** 13.6A Governance Lifecycle and Derived Lifecycle State

**Normative Statement:** Internal processing states SHALL NOT become canonical externally visible governance states. Only Derived Lifecycle State established through permitted lifecycle transitions and authoritative governance records SHALL be exposed as canonical lifecycle state.

**Relationship:** Specifies — Direct

**RTM Test Assertion:** Exercise the violating or negative path and verify that the implementation enforces: Internal processing states SHALL NOT become canonical externally visible governance states. Only Derived Lifecycle State established through permitted lifecycle transitions and authoritative governance records SHALL be exposed as canonical lifecycle state.

**Procedure**

1. Establish the controlled TC-011 baseline using the Test Inputs and Setup, with all conditions unrelated to TC-011-A01 held valid and recorded.
2. Create a conforming control in which the implementation can satisfy the following exact obligation without relying on an unrelated refusal: Internal processing states SHALL NOT become canonical externally visible governance states. Only Derived Lifecycle State established through permitted lifecycle transitions and authoritative governance records SHALL be exposed as canonical lifecycle state.
3. Identify the authorized external state-retrieval interface and the implementation's internal processing-state source so the two observations can be distinguished.
4. Start governance processing and hold or observe the Proposal while one or more implementation-internal transient states exist but before an authoritative lifecycle outcome has been established.
5. Query the external interface during processing and verify that it returns only an allowed authoritative or previously established Derived Lifecycle State and does not expose internal queue, worker, retry, validation, or orchestration states as canonical governance state.
6. Complete the permitted lifecycle transition, query the external interface again, and verify that the newly returned state is supported by the authoritative governance decision and ordered governance records.
7. Attempt an unauthorized, wrong-tenant, wrong-domain, wrong-scope, or stale retrieval and verify denial or appropriately constrained output without cross-boundary disclosure.

**Expected Result**

Authorized callers can retrieve the applicable authoritative Derived Lifecycle State, but transient internal processing states never become canonical externally visible governance states. The returned state is tenant-, domain-, scope-, and Proposal-bound and is supported by authoritative governance records.

**Required Evidence**

- External state-interface request and response during internal processing
- Internal transient-state observation retained only for assessor comparison
- Authoritative lifecycle decision and ordered lifecycle records
- External state-interface response after the authoritative transition
- Authorization, tenant, domain, scope, and Proposal binding evidence
- Unauthorized or mis-scoped retrieval result

**Pass Criteria**

TC-011-A01 passes only when the external interface is usable by an authorized caller, exposes only authoritative Derived Lifecycle State, never exposes transient internal state as canonical, and enforces all applicable access and boundary constraints, thereby independently demonstrating the complete requirement of NS-13.6A-03.

**Failure Conditions**

TC-011-A01 fails if any required trigger, validation, transition, binding, outcome, or evidence element described above is absent or contradicted; a generic refusal occurs without proving the statement-specific basis; an invalid, stale, substituted, unauthorized, out-of-scope, or bypass path is accepted; a prohibited governed consequence occurs; or the result cannot be independently reproduced from attributable authoritative evidence.
