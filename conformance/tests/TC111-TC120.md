# AGCP Conformance Test Cases TC-111 through TC-120

This file contains the current RTM-synchronized AGCP Conformance Test Cases for the indicated range. Each Test Case distinguishes direct test-generating Normative Statements, conditional Normative Statements, and supporting/contextual relationships.

A Test Case claims direct verification only when the corresponding assertion includes a procedure, expected result, required evidence, and pass/failure criteria.

# TC-111 — Constitutional Validation

## Purpose

Verify that the implementation satisfies **CR-111** by exercising the controlled scenario below and independently verifying every direct test-generating Normative Statement assigned by the current AGCP Requirements Traceability Matrix.

## Authoritative Traceability

- Primary Conformance Requirement: **CR-111 — Constitutional Validation**
- Requirement Text: Governance artifacts SHALL undergo constitutional validation prior to activation.
- Requirement Group: RG-12 — Governance Compilation & Control Plane Integrity
- Applicable Conformance Level: L3 — Deterministic Governance
- Direct Test-Generating NS IDs: NS-15.5-03, NS-15.6A-03
- Conditional NS IDs: None
- Supporting/Contextual NS IDs: NS-15.2-03

## Test Objective

A controlled proposal, governance artifact, or implementation condition is configured to exercise CR-111: Governance artifacts SHALL undergo constitutional validation prior to activation.

## Preconditions

- The implementation is configured for the claimed conformance level and implementation profile.
- All inputs unrelated to the condition under test are valid, current, attributable, and within the same defined evaluation horizon unless a subtest expressly changes them.
- The implementation exposes governance decisions, lifecycle outcomes, enforcement results, and Governance Evidence sufficient for independent assessment.
- Equivalent-input repetitions use the same qualified semantics, governance configuration, applicable policy, Canonical State, and ordering conditions.
- No implementation-specific extension may weaken, replace, or bypass the requirement or any directly mapped Normative Statement.

## Test Inputs and Setup

- Test Scenario: A controlled proposal, governance artifact, or implementation condition is configured to exercise CR-111: Governance artifacts SHALL undergo constitutional validation prior to activation.
- A controlled Proposal, Action Representation, Governance Context, Canonical State reference, policy set, authority context, tenant/domain context, execution context, and governance configuration sufficient to exercise CR-111.
- Scenario trigger: Governance artifacts SHALL undergo constitutional validation prior to activation.
- Component coverage: Delegation and Authority Lineage, Governance Self-Protection.
- A conforming variation that satisfies all mandatory inputs, constraints, authority conditions, policy conditions, state conditions, and evidence requirements applicable to the mapped Normative Statements.
- A negative variation that withholds, invalidates, mutates, reorders, substitutes, or bypasses the specific prerequisite, constraint, state, authority, artifact, evidence, or processing behavior governed by each mapped Normative Statement.
- Observation Window: Long enough to capture synchronous and asynchronous authoritative outcomes for the processing attempt.
- Negative-Control Rule: Each adversarial or invalid variation changes only the condition identified by the applicable subtest.

1. Load the baseline tenant, governance domain, proposal or controlled artifact, policy, qualified authoritative sources, governance configuration, and evidence prerequisites.
2. Execute the primary scenario for CR-111 and record the complete governance-stage sequence and authoritative outcomes.
3. Execute each direct Normative Statement subtest below using an isolated processing attempt or a clearly identified phase of the same attempt.
4. Execute the conditional subtest when its applicability condition is present; otherwise document Not Applicable with implementation-profile evidence.
5. Inspect supporting and contextual constraints as integrated properties of the test path without counting them as separate direct NS verifications.

## Direct Normative Statement Verifications

### TC-111-A01 — NS-15.5-03

**Core Specification Section:** 15.5 Governance Outcomes

**Normative Statement:** Governed re-evaluation SHALL require successful validation before activation.

**Relationship:** Specifies — Direct

**RTM Test Assertion:** Exercise the mapped CR scenario and verify: Governed re-evaluation SHALL require successful validation before activation.

**Procedure**

1. Establish the controlled TC-111 baseline using the Test Inputs and Setup, with all conditions unrelated to TC-111-A01 held valid.
2. Execute the valid path through Governance Self-Protection processing and capture ordered evidence for each prerequisite and downstream step.
3. Attempt a controlled bypass or out-of-order invocation that omits the prerequisite or invokes the downstream step early.
4. Verify that the valid path respects the required order and that the out-of-order path is refused or cannot produce the governed consequence.
5. Confirm ordering from authoritative sequence or ledger information rather than timestamps alone where ledger ordering applies.

**Expected Result**

The required sequencing in TC-111-A01 is preserved; bypass or premature downstream processing cannot produce an authoritative governance or execution result.

**Required Evidence**

- Ordered governance-stage records
- Bypass or out-of-order attempt
- Refusal/prevention evidence
- Authoritative ordering or sequence evidence

**Pass Criteria**

TC-111-A01 passes only when the observed behavior and retained evidence independently demonstrate the full requirement of NS-15.5-03.

**Failure Conditions**

the expected behavior is absent or contradicted; required evidence is missing, inconsistent, or not attributable; a prohibited or bypass path produces a governed consequence; the observed result cannot be independently verified.
